# v8.0 虛擬書房（階段 1–3）

發布日期：2026-10-17

把以畫布為主的工作台改造成**「溫和陽光下的半擬 3D 木色書房」**：書桌上嵌原有畫布、書架把每張筆記卡呈現為一本書，並可建立分類櫃板與標籤。本輪只做階段 1–3（視覺骨架、書架與書本、分類櫃板）；IndexedDB 與 WebRTC（階段 4–5）留待下一輪，但資料結構已預留介接點。

---

## 1. 五個已確認決策的實作方式

| 決策 | 實作 |
|---|---|
| ① 只做階段 1–3 | 無 IndexedDB／WebRTC／跨裝置同步。`store.ts` 仍是唯一真相；遠端介接預留 `updatedAt`、內容/佈置分欄與純函式 `applyPatch`。 |
| ② 書脊＋抽出預覽 | 平時只顯示書脊（`BookSpine`：書名直排、分類色條、形狀色、厚度/高度微差異）。桌機 hover／手機第一次點擊 → 書脊 `translateZ` 前移＋「書封預覽」卡（標題、領域、推理形狀、摘要首行）。再點一次或「開啟筆記卡」→ 既有 `CardDetailModal`（**單一渲染路徑**，沒有書架專用閱讀器）；「在畫布定位」→ `InfiniteCanvas.apiRef.focusCard()` 置中並選取。 |
| ③ 單一分類 | `StudyBookLayout.categoryId: string \| null`（null = 未分類）；一本書只出現一個櫃板，無多分類、無重複書本。 |
| ④ 可自由旋轉的 3D 視角 | **CSS 3D**（`perspective: 1500px` + `transform-style: preserve-3d` + 分層平面），**不用 three.js**：畫布上的 `InfiniteCanvas` 仍是真正的 HTML，事件、輸入框、IME 全部正常。環繞只對單一 `.study-room-3d` 容器做 `transform`（ref + `requestAnimationFrame`，拖曳中不重算 React state）；角度限制 yaw ±28°、pitch −6°～+14°，有「重置視角」；「平移 ↔ 環繞」模式切換，觸控裝置預設平移。 |
| ⑤ 本輪不做同步 | 不引入 WebRTC／STUN／signaling。所有實體都有 `updatedAt`；內容變更（cards 等）與空間/佈置變更（canvasObjects、studyBooks）分欄存放；`applyPatch(state, patch)` 為純函式更新入口，下一輪接 op log 可直接以 patch 形式套用遠端操作。 |

### 為什麼不用 three.js（重點說明）

1. **畫布必須是真 HTML**：`InfiniteCanvas` 內有 textarea／輸入框／KaTeX／IME 與 Pointer Events 手勢。WebGL 紋理化或 canvas 模擬都會破壞輸入與可及性。
2. **CSS 3D 夠用**：半擬 3D 只需要厚度、光源、前後層次；`perspective` + `preserve-3d` + 分層平面即可表達，且動畫只有 transform，符合「不引入大型依賴」規則。
3. **手勢可精確切分**：DOM 事件冒泡讓「畫布 vs 環繞」可以靠 `closest()` 規則乾淨分派（見 §4）。

### 書桌平面為什麼不隨視角旋轉

CSS 3D 透視變換是投影映射（非仿射），`InfiniteCanvas` 以 `getBoundingClientRect()` 做螢幕↔畫布座標換算；若畫布平面被 3D 旋轉，拖卡會漂移、文字變形。因此：

- **旋轉**：牆面、光源、地板、書架（`.study-room-3d` 內，含書本 `translateZ` 抽出效果）。
- **不旋轉**：書桌＋內嵌畫布（`.study-desk-fixed`，面向使用者的固定前景）。
- 視角感由環繞的家具/牆面表達；畫布保持可讀、可操作。書桌的拖曳（木框區域）仍會觸發環繞——它是「家具」，只有畫布表面（`data-canvas-surface`）的手勢完全交給畫布。

## 2. 視覺規格

- 半擬 3D：看得懂厚度、光源、前後層次；材質不寫實。
- 色票：淺橡木 `#d9b98a`／蜂蜜木 `#c79a5b`／深棕 `#8a6440`；牆面米白 `#f3ece0`／暖灰 `#e6ded2`／奶油 `#faf5ea`；光線淡金 `#fff3d6`（單一主光源左上，陰影往右下）；畫布紙面 `#faf7ee`（與 v7.2 紙張一致）。
- 書本低飽和：`desaturateColor()`（HSL 降飽和＋亮度夾限）沿用形狀/節點色，不做高彩度色塊。
- 家具：書桌（桌板＋前緣厚度）、書架（側板＋層板＋背板＋櫃板隔板）、紙膠帶標籤。
- 動態顏色一律 inline style（Tailwind 無法 runtime 換色）。
- 效能：環繞只動單一容器 transform；書脊 `content-visibility: auto`（>200 本仍可用）；書本拖曳只有目標改變時才 setState。
- 列印：`@media print` 隱藏整個書房（`.study-room-view` 等），只輸出卡片紙面（v7.2 規則）。

## 3. 資料模型與 STORAGE_KEY 遷移

新增 `src/lib/study.ts`：

```ts
StudyCategory   { id, name, order, color, createdAt, updatedAt }
StudyBookLayout { cardId, categoryId: string | null, orderInShelf, spineColor?, updatedAt }
StudyLayout     { camera: { yaw, pitch }, shelfRows }
```

- **一卡一書（1:1）**：`StudyBookLayout.cardId === CardData.id`；`createCard` 建書、`deleteCard` 刪書、載入/匯入時 `ensureStudyState` 補齊（缺則補、孤兒移除）。
- **關聯以 `categoryId` 為準**，不用名稱；改名不影響任何書。
- **書脊顏色優先序**：`spineColor` → 畫布物件 `style.accentColor`（v7.2 節點色）→ 形狀預設色（A–E/COMPOSITE）。v7.2 的節點顏色自然反映到書架。
- **佈置 ≠ 座標**：移動書本只改 `orderInShelf`／`categoryId`，**不動 `CanvasObjectData.x/y`**；移動畫布卡片也不改書本排序（`scripts/check-study.ts` 驗證雙向隔離）。
- **「未分類」**：系統保留分類（id `cat-uncategorized`），不可刪除、不可改名為空、恆在最後；新卡預設進未分類（`categoryId: null`）。

### STORAGE_KEY：`scinotes-workspace-v7.1` → `scinotes-workspace-v8.0`

1. 載入時先讀 `scinotes-workspace-v8.0`；沒有再讀舊 key `scinotes-workspace-v7.1`。
2. 讀到舊資料 → `applySchemaMigrations` → `ensureStudyState` 補齊：`studyCategories`（至少一筆「未分類」）、每張卡一筆 `StudyBookLayout`、`studyLayout`（視角夾限＋層數），然後寫入新 key。
3. **舊 key 保留不刪**（備份）；舊資料內容不掉，只補齊缺欄。
4. JSON 匯出帶 `schemaVersion: 8` 與全部書房資料；舊檔匯入自動補齊。

## 4. 手勢衝突怎麼處理（畫布 vs 環繞）

| 起點 | 手勢歸屬 |
|---|---|
| 畫布表面（`data-canvas-surface`） | 100% `InfiniteCanvas`：平移、框選、拖卡、雙指縮放、雙擊開卡 |
| 書房背景／家具（牆、地板、書架側板/層板/背板、書桌木框） | 環繞視角（模式＝「環繞」時） |
| 書本書脊 | 點擊＝抽出/開卡；拖曳＝重新排列/換櫃板（Pointer Events，閾值 6px） |
| 任何輸入框／按鈕／預覽卡 | 不觸發環繞（`stopPropagation`＋`[data-no-orbit]`） |

實作：

1. 環繞的 `pointerdown` 掛在書房外殼，先做排除：`closest("[data-no-orbit], button, input, textarea, select, a")` 命中就放棄；畫布鑲嵌面帶 `data-no-orbit`。
2. **模式切換鈕（平移 ↔ 環繞）**：`pan` 模式下背景拖曳完全不環繞（捲動/畫布優先）；觸控裝置預設 `pan`，桌機預設 `orbit`——手機一根手指不會被搶走。
3. 書本拖曳用 `window` 層 pointermove/up（pointer capture 語意），拖曳結束的合成 click 以 `suppressClick` 吞掉，不會誤開卡片。
4. 「在畫布定位」走 `InfiniteCanvas` 的 `apiRef.focusCard(cardId)`（置中＋選取），不重寫任何畫布邏輯。

## 7. 已知限制

- 書桌面固定不隨環繞旋轉（刻意：保持畫布座標精確），視角感來自牆/書架/地板。
- 櫃板內排序、跨櫃板移動用拖曳＋分類面板上下鍵（無鍵盤拖書快捷鍵）。
- `shelfRows` 依書量自動估算（估寬打包），未提供手動增減層板。
- 書本拖曳在觸控裝置採 `touch-action: pan-y`：可水平拖書、垂直捲動書架。
- 階段 4（IndexedDB）、階段 5（WebRTC）未做；`applyPatch` 與 `updatedAt` 已預留。
