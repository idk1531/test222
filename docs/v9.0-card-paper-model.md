# v9.0 卡片知識系統與紙面資料模型

## 已確認並實作

- **知識系統**＝一個工作區中的卡片集合；**卡片**＝欄位紙實例的集合；**紙**＝某個欄位的一份實例，是資料抽象，不代表實體紙張。
- 卡頭包含紙目錄，列出每份紙的紙號、欄位與備註。紙號依目前目錄順序編排；紙 ID 穩定，不以紙號作為身分。
- 卡片的探究組採同層、平等呈現，且每組從「情境」開始；「推演與思路」由交替的思路／推演步驟組成，後續步驟可記錄承接前一段的連結；其餘欄位為「整理（選填）」、「回收」、「輸出」。
- 第一組的舊資料遷移與相容策略不刪除 v8 原欄位；舊背景與情境、構造思路、計畫／候選、閉卷草稿及 WHY 推導複製到首個探究的對應位置，舊欄位仍留在匯出資料及 v8 備援表單中。
- WHAT、APPLY、關係邊、過程日誌、診斷標籤仍以既有資料與規則呈現；附錄 A–C 規則未隨紙面重組而更動。讀法與視角仍屬 WHAT。
- 卡片紙面主題新增黑底金字「曜黑金箔方格」；全域介面主題選單另新增「曜黑金字」。

## 待確認（附錄 D.5）

探究紙組重複的完整規則與 D.5 第二組其他未決事項尚未定案。為了讓 v9 資料模型可以實際操作，目前提供新增／刪除同層探究組的**暫行介面**；程式與 UI 均明示「暫行／待確認」，不能視為 D.5 已確認規則。本版不替其他未決事項自行補規則。

## 資料模型與遷移

- `WorkspaceState.cards` 是工作區（知識系統）的卡片集合。
- `CardData.inquiries` 儲存可重複的探究組；`steps` 依序正規化為 `thinking → derivation → thinking → derivation…`。
- `CardData.papers` 儲存每份欄位紙的穩定 ID、目錄序號、欄位、內容參照、所屬探究（如適用）及備註。紙張正文仍放在既有 typed card fields／工作區關係與日誌集合中，避免複製 WHAT/APPLY 等既有內容並維持 v8 讀者相容。
- `SCHEMA_VERSION=9`、本機儲存鍵 `scinotes-workspace-v9.0`。讀取 v8.0／v7.1 本機備份與匯入舊 JSON 都會執行冪等遷移；舊欄位不刪除。

## 驗證

- `npm run test:card-papers`：驗證舊文字遷移與原欄位保留、紙目錄及動態紙號、探究步驟交替。
- `npm run typecheck`、`npm run export`：程式型別與靜態匯出驗證。
- 黑底金字包含既有 WHAT/APPLY 元件；中性白／灰面板在該預設下套用深色覆寫。未將未經實際瀏覽器檢視的畫面宣稱為目視驗收完成。
