# v8.4 書房互動規格（6 項）：開書見卡、拿起／放下、桌上直開、視準、跳躍與碰撞、坐下

日期：2026-10-18　基準：`main`（含 v8.2 貼圖、v8.3 視覺還原）
本份是**唯一規格來源**，只覆蓋下列 6 項；§5 明列本輪不做的事，不要順手擴。
⚠️ 開工前先 `grep` 確認錨點仍在（v8.3 動過 `RoomGeometry`／`Book3D`／`room3d`，**行號會飄、符號名穩定**）。

| # | 需求 | 一句話定義 |
|---|---|---|
| 1 | 書本打開顯示卡片 | 準心對準書本按下 → 直接開 `CardDetailModal`（不再兩段式） |
| 2 | 從桌上拿到手中／從手中放到桌上 | 手持書是**跟隨相機的 3D 物件**；放置寫入桌上位置 |
| 3 | 桌上的書直接開啟，**畫布保留不動** | 開卡**不得**飛進工作視角、不得重置 pan/zoom |
| 4 | 電腦版視角跟隨準心 | Pointer Lock；鎖定後**以畫面中心 raycast** |
| 5 | 跳躍＋書桌碰撞箱 | 現在能穿桌 → 家具級 AABB；`Space` 跳（頂高 ≈0.56 m） |
| 6 | 椅子可以坐下 | 坐下後視高降到 1.18、可坐著滑動；起立不得死鎖 |

## 0. 紅線（任一踩到就退回）

1. **`InfiniteCanvas` 手勢與座標換算不動**（pointer 邏輯、`getBoundingClientRect()` 純仿射、雙指縮放、框選、IME）。
2. **資料層只加選填欄位**：`SCHEMA_VERSION` 維持 8、`STORAGE_KEY` 不變；舊檔載入行為 100% 不變；匯出 JSON 自然帶出新欄位。
3. **`CameraRig` 的工作視角進出 (`beginFlight("work"|"room")`) 不改**；桌上開卡是**另一條路徑**。
4. **既有 accessibility 路徑不退**：「書架目錄」的 Tab 可達清單（`min-h-10` touch-target）必須保留。
5. `scripts/check-room3d.ts` 現有兩條邊界斷言（`edge.x === ROOM.width/2 - CAMERA.wallMargin` 等）**不可改寫**。
6. Gate 基線：typecheck 0 errors｜lint 11 problems（6 err／5 warn，既有）**新增 0**｜`check-study`／`audit`／`build`／`STATIC_EXPORT=1 NEXT_BASE_PATH=/test222` 全綠。

## 1. 先定兩件真相，6 項才有共同地基

### 1.1 一本書在哪裡（`src/lib/study.ts`）
```ts
export interface StudyBookLayout {
  cardId: string;
  categoryId: string | null;
  orderInShelf: number;
  /** v8.4 選填：缺省＝在書架上（舊資料完全不變） */
  place?: "shelf" | "desk";
  /** 僅 place==="desk" 有意義；房間座標系，公尺 */
  desk?: { x: number; z: number; yawDeg: number };
}
```
- `makeBookForCard()` **不寫** `place`（新卡保持瘦）。`ensureStudyState` 只做防禦：`place==="desk"` 但缺 `desk` → 退回 `"shelf"`；**不補預設值**（選填即語意）。
- **必做**：`computeShelfLayout()`（`room3d.ts`）要 `filter` 掉 `b.place === "desk"` 的書，否則桌上的書會同時出現在架上（最常見的實作漏洞）。`orderInShelf` 不清除、不重編——放回架上即回原位。
- `store.ts` 新增 action（與 `reorderBook` 同區塊、同一持久化路徑）：
  `setBookPlace(cardId, place: "shelf"|"desk", desk?: {x:number;z:number;yawDeg:number})`
- **「拿到手上」是瞬態，不入資料層**：`StudyRoomView` 的 `const [heldCardId, setHeldCardId] = useState<string|null>(null)`。重新整理不會卡在手上。

### 1.2 一張表驅動全部點擊／按鍵（`src/lib/roomActions.ts`，純函式）
```ts
export type HitKind = "book" | "heldBook" | "deskPaper" | "chair" | "none";
export type InputKey = "click" | "shiftClick" | "rightClick" | "KeyE" | "KeyQ" | "KeyF" | "Space";
export interface RoomActionCtx {
  mode: "room" | "work"; flying: boolean; held: string | null; seated: boolean;
  bookOnDesk: boolean;          // 命中物是 place==="desk" 的書？
  hitDeskSurface: boolean;      // 準心是否命中桌面（放書用）
  seatedCanStand: boolean;      // 起立後頭部是否安全
}
export type RoomAction =
  | { type: "openCard"; cardId: string; from: "shelf" | "desk" }
  | { type: "openPreview"; cardId: string }        // v8.1 既有（排序／換分類）
  | { type: "pickUp"; cardId: string }
  | { type: "putOnDesk"; x: number; z: number; yawDeg: number }
  | { type: "returnToShelf" }
  | { type: "enterWorkView" } | { type: "sit" } | { type: "stand" }
  | { type: "jump" } | { type: "noop" };
export function resolveAction(hit: HitKind, key: InputKey, ctx: RoomActionCtx): RoomAction;
```
| 命中 | `click` | `Shift+click`／右鍵 | `E` | `Q` | `F` | `Space` |
|---|---|---|---|---|---|---|
| 架上書 | **`openCard{from:"shelf"}`**（#1） | `openPreview`（保留排序／換分類入口） | `pickUp` | — | — | — |
| 桌上書 | **`openCard{from:"desk"}`**（#3） | `openPreview` | `pickUp` | — | — | — |
| 手上書 | `putOnDesk`（`hitDeskSurface` 才放，否則 noop＋提示） | `returnToShelf` | `putOnDesk` | `returnToShelf` | — | — |
| 桌紙面（`userData.kind==="deskCanvas"`） | `enterWorkView`（v8.1 不變） | — | — | — | — | — |
| 椅子 | `sit`（在 trigger 內）／`stand`（已坐） | — | — | — | `sit`/`stand` | — |
| none | `noop` | — | — | — | `stand`（僅 seated） | `jump`（僅 room 模式、`!seated`） |
**統一規則**：`ctx.mode==="work"` 或 `ctx.flying` → 一律 `noop`（沿用 v8.1「飛行中拒收輸入」「工作視角 WASD 對畫布無效」）。
`resolveAction` 的**每一格都要有單元測試**（放 `scripts/check-room3d.ts`，14 行換掉一整類回歸）。

## 2. 六項規格

### #1 書本打開顯示卡片
- 行為改了：v8.1 是「點書 → HTML 書封預覽 → 再按『開啟筆記卡』」。本輪**左鍵直開 `CardDetailModal`**，預覽降為 `Shift+click`／右鍵（以及「書架目錄」清單）——排序與換分類不能失去入口。
- 接線：`Book3D.tsx` 的 `userData.cardId`／`categoryId` 已是命中索引（沿用）；`StudyRoomView.tsx` 的 `handleOpenCard(card)` 就是目標動作；把 `openBookPreview(cardId)` 掛到修飾鍵分支。
- 觸控（無右鍵）：長按 = `openPreview`（`pointerup` 前 450 ms 判定；不要在 `InfiniteCanvas` 裡做，只在書房 raycast 路徑做）。
- 可選的「書打開」感（P3 再說，別提前）：`CardDetailModal` 收 `openFrom?: {x:number;y:number}`，用 `projectToScreen(bookWorldPos, camera, dom)`（`room3d.ts` 已有）算原點，進入動畫從書的位置 `scale(0.94)→1` ＋ 220 ms；`prefers-reduced-motion` 時關閉。
- 開卡期間**房間暫停渲染**：`api.setActive(false)`（v8.1 已有此慣例），關閉時恢復。

### #2 拿起／放到桌上
- 新增 `src/components/HeldBook.tsx`：`api.camera.add(group)` → **書天生跟著視準**，不要自己疊 yaw/pitch。本地 `position (0.24,-0.17,-0.42)`、`rotation (-0.16,-0.32,0.08)`。
- 書本幾何**複用 `Book3D.tsx` 的建模函式**（材質共享，≤120 三角）；封面／書脊色沿用 `resolveSpineColor` 優先序 `spineColor → accentColor → 形狀色`，否則三處顏色會不一致。
- 行進搖曳：`api.addFrameCallback((dt,t)=>{ g.position.y = base + Math.sin(t*1.9)*0.006 })`，**只在 held 非空時註冊**，unbind 存進 cleanup。
- 拿起：`pickUp` → 若原在架上，`setBookPlace(cardId,"desk")` **不要**在拿起瞬間寫入；先只改 `heldCardId`（純 UI）。放下才落地寫 store（避免「拿起就刷新」留下幽靈桌上書）。
- 放下：`putOnDesk{x,z,yawDeg}` — `x/z` 取**準心射線與桌面（`deskPaper` 或桌板 mesh）的交點**，未命中桌面 → 不放置並顯示提示「把準心對準桌面」；`yawDeg = round(playerYawDeg/15)*15`、位置吸附 `DESK_SNAP = 0.04`（整齊且可復現）。
- 位置合法性：夾在桌板範圍內（用 §2.5 的 `DESK`/L 形桌 footprint；`clampToDesk(x,z)` 純函式，可單測）。
- 回架：`returnToShelf` → `setBookPlace(cardId,"shelf")`，`orderInShelf` 原值保留 → `computeShelfLayout` 自動回填。
- 卸載：`camera.remove(group)` ＋ dispose（照 `StudyScene` 慣例）；`mode==="work"` 進入時**強制把手上的書先放回原處**（`held=null`，不寫 store），別讓手裡的書飛進工作視角。

### #3 桌上的書直接開啟，畫布保留不動
- `openCard{from:"desk"}` **只**開 modal：不得呼叫 `beginFlight("work")`、不得碰 `canvasApiRef.current?.focusCard()`、不得動 `setWorkMode`。
- 可測契約（進 `scripts/check-study.ts`）：呼叫前後 `studyLayout.camera` 與 `canvasObjects` 每筆 `x/y/width/height` **deep-equal**，且 `workMode === false`。
- 與「在畫布定位」區隔：需要飛過去時，用 modal 內的次要連結（按了才 `locateBook`）；**桌上書的 HTML 預覽浮層不顯示「在畫布定位」主按鈕**（v8.1 那顆按鈕在書本預覽裡，保持架上書的行為不變即可）。
- 桌上書本與紙面重疊時的命中優先：**書本 > 紙面**（`intersectObjects` 依 `userData.cardId` 先篩，或給書本 `renderOrder`＋過濾）。實作寫成一行註解說明取捨。

### #4 電腦版相機視角跟隨準心（Pointer Lock）
`CameraRig.tsx`（已有 `stateRef.yaw/pitch`、`pointerRef` 拖曳、`clampPitchRad`、`CAMERA.lookSensitivity`）：
1. `canvas` 上的 `click` → 桌機（`matchMedia("(pointer:fine)")`）且 `modeRef.current==="room"` 且 `!flyingRef.current` → `canvas.requestPointerLock()`（**回傳 Promise，要 `.catch()`**，Chrome 對短間隔重複請求會 reject）。
2. 鎖定中改用 `mousemove` 的 `e.movementX/movementY`；拖曳路徑開頭加 `if (document.pointerLockElement) return;` → **避免雙倍位移**（最容易踩的 bug）。
3. 鎖定中的 `pick()`：NDC **固定 (0,0)**（現有程式由 `clientX/clientY` 算，鎖定期那個座標是凍結的）。這才是「跟隨準心」的正解。
4. 自動解鎖：`pointerlockchange` 監聽；`preview`／`showCatalog`／`showCategoryPanel`／modal 任一開啟、或 focus 進入 `input/textarea/contenteditable` → `document.exitPointerLock()`（與 v8.1「輸入框聚焦不走動」同一個 effect 群）。`Esc` 由瀏覽器自動解鎖，UI 要顯示「點擊鎖定／ESC 解除」提示。
5. 準心：中心 3px 圓點，`pointer-events:none`，只在鎖定時可見，`@media print` 隱藏。
6. 靈敏度不動 `lookSensitivity=0.0042`；**新增** `CAMERA.lockSensitivity = 0.0022`（鎖定後無系統加速度，實測微調）。
7. 手機／平板完全不走這條路（拖曳環顧＋搖桿不變）；`mode==="work"` 進入時務必解鎖，否則畫布吃不到滑鼠。
8. 持久化：鎖定與否**不寫入 localStorage**；`storeCamera()` 開鎖期間照常（位置會變，這是既有語意）。

### #5 跳躍＋書桌碰撞箱
全部走純函式（`room3d.ts`，SSR 安全、可單測、不碰 three 的 renderer）：
```ts
export interface Aabb { minX:number; maxX:number; minZ:number; maxZ:number; top:number; standable:boolean }
export const COLLIDERS: Aabb[];   // 由 DESK／L 形桌＋深炭櫃（同一 footprint）／SHELF／CHAIR 推導
export function resolveCollision(x:number, z:number, radius=0.22): {x:number; z:number};
export function groundHeightAt(x:number, z:number): number;   // 本輪一律 0
export const JUMP = { velocity: 3.6, gravity: 11.5 };         // 頂高 v²/2g ≈ 0.56 m
export function clampToDesk(x:number, z:number): {x:number; z:number};   // #2 用
```
- `resolveCollision`：**分離軸**（先 X 後 Z）推開，半徑 0.22 → 斜向撞牆角不會卡死。接線在 `CameraRig` 每幀算出新 `x/z` 後、寫回 `stateRef` 前；`clampRoomPosition`（牆）**保留、順序在後**。
- **`COLLIDERS` 需要的 `CABINET`／`CHAIR` 若目前是寫死在 `RoomGeometry.tsx`，先補成 `room3d.ts` 具名 const**，讓幾何與碰撞同一真相；**嚴禁在元件裡另抄一份數字**（v8.3 那類「背板空腔」偏差就是這麼來的）。
- 跳躍：`vy` 存 `stateRef`；`onGround` 才能跳；`camera.position.y = clampHeight(base) + jumpOffset` → **跳躍不污染持久化的 `height`**（`base` 仍由滾輪 `wheelHeightStep` 控制）。
- `Space` 衝突：畫布視圖的 `Space＝平移`（README 快捷鍵）→ 只在 `mode==="room"`、未鎖輸入框、`!seated` 時吃跳躍；焦點在 `<button>` 上不得觸發。
- **明確決定：桌面不可站立**（`standable:false`、`groundHeightAt→0`）。理由：站上 0.78 m 後近裁剪、桌上 HTML 浮層對齊全崩。`standable` 布林先預留，未來要開再連同投影錨定一起做。
- 手機同受益（O(1) 純算式）；手機不給跳躍按鈕。

### #6 椅子可以坐下
```ts
export const SIT = { triggerRadius: 0.34, seatY: 0.42, eyeY: 1.18, walkSpeed: 1.15, fov: 58, fadeOpacity: 0.25 };
```
- 先 `grep -n "Chair\|chair\|sit" src/components/`：v8.3 若已建椅就取用同一個 `chairGroup`；**若尚未建模，本輪連幾何一起補**（附錄 A）。
- 坐下條件：玩家水平距離椅座中心 < `triggerRadius`，`F` 或點擊椅子（走 `resolveAction`）。
- 坐下後：**椅子跟隨玩家**（`chairGroup.position.lerp(playerPos, 0.18)`、`chairGroup.rotation.y = playerYaw`）→ 「坐著滑著走」，只有 3 行卻比鎖死位置好；`height` 以 0.24 s `easeInOutCubic`（`room3d.ts` 已有）過渡到 `SIT.eyeY`；`FOV` 62→58；移動速度上限 `SIT.walkSpeed`；`jump` 封鎖；`pitchMin` 放寬到 −80°（坐著會低頭看書）。
- 人在椅殼內會糊臉 → 坐下時椅殼 `opacity → 0.25`（`transparent`），起立復原。
- **起立不得死鎖**：站起後若與桌底重疊（`seatY+1.5 > DESK.top` 區域），先用 `resolveCollision(x, z, 0.30)` 推到自由點再起立；測試案例必須覆蓋「坐著滑進桌下 → 按 F → 能出來」。
- 起立輸入：`F`／`Esc`／HUD 按鈕。手機與鍵盤：trigger 內顯示「坐下／起立」`touch-target min-h-10`（與「書架目錄」同慣例）。

## 4. Gate（每筆都重跑）

新增斷言最低限度：

- 人工（沙箱無法截 WebGL，見 `docs/v8.4-headless-visual-verification.md`）：鎖定進出與延遲感、穿桌是否真的擋住、坐下滑行、開卡時預覽入口沒不見。

## 5. 本輪明確不做

- 不改造卡片在**畫布上的外觀**、不做「卡片頁＝書本頁」、不做翻頁動畫或書脊裝訂視覺——本輪書只是**入口與物件**，卡片仍是既有 `CardDetailModal` 的紙面（含 v7.2 紙上編輯）。
- 不做 3D 拖書（v8.1 已因「raycast 拖曳與觸控環顧互搶」拒絕；本輪是「按鍵拿起＋準心放下」）。
- 不做書本物理（堆疊、掉落）、站上桌面、家具級滑動碰撞、日夜／同步／IndexedDB。
- 不動 `InfiniteCanvas`、`seedData.ts`、`inspect.ts`、列印路徑。

## 附錄 A：椅子最省事的建模（僅當 v8.3 未建）
- 座面：`CylinderGeometry(0.30, 0.30, 0.07, 20)`，y=`0.42`。
- 靠背／殼：`CylinderGeometry(0.32, 0.32, 0.34, 20, 1, true, Math.PI*0.75, Math.PI*1.5)`（**開口圓柱殼**，一次成型出抱背輪廓），`side: DoubleSide`。
- 腳：4×`CylinderGeometry(0.011,0.011,0.40,6)`，外八 8°，`metalness .8 roughness .35`。
- 材質：`#b3a08c`、roughness 0.66；全椅 ≤900 三角；`userData.kind="chair"`；`castShadow:true`。
- 位置：`(0.55, 0, 0.62)`，初始 `rotation.y = 2.55`（面向桌）。
