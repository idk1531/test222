## 1. 本輪目標與取捨

把「書房參考圖提示詞包 v2」拍板的結果（**布局、材質、家具、燈光跟圖一；唯獨窗外保留綠意庭園**）落成 App 的實際材質來源，
而不是只出一張示意圖。原則三條：

1. **只換 albedo 來源，不改場景架構**：`StudyScene`／`CameraRig`／`InfiniteCanvas` 浮層／書本 3D 全部沿用 v8.1。
2. **照片貼圖一律可退回**：3D 元件先用既有程序化 canvas 紋理把房間建好，再非同步換上照片貼圖；
   載入失敗（無資產、離線、404）就靜默留程序化版本。`TEXTURES.enabled = false` 即完全回到 v8.1 視覺，
   也維持「純前端、離線可用」的行為契約。
3. **不做 normal／roughness／HDR env**：現有 `MeshStandardMaterial` 的 roughness 與 ACES 色調映射已提供光影，
   再疊一層貼圖光照會雙重打光，且體積翻倍。本輪只吃 albedo。

## 3. 資產清單與產製流程

`public/textures/study-room/`（6 檔，共 988 KB，sRGB JPEG q88）：

| 檔案 | 尺寸 | 平貼 | 用途 |
|---|---|---|---|

| `oak-floor.jpg` | 1024² | ✓ | 地板（預設） |

| `plaster.jpg` | 1024² | ✓ | 四面牆 |
| `garden-view.jpg` | 1536×717 | ✗ | 窗外遠景（依 `sky` 平面 15:7 裁切，避免拉伸） |
| `book-spines.jpg` | 1376×768 | ✗ | 書架背板暗景 |

**產製**：來源是提示詞包 §7 的六段材質提示詞生成的 `tex-*.png`（1024²，AI 宣稱 seamless 不可信），
再用 `scripts/make-room-textures.sh` 轉成真正無縫的平貼圖：

```bash
bash scripts/make-room-textures.sh <來源圖目錄> public/textures/study-room
QUAL=82 TILE=1536 bash scripts/make-room-textures.sh ...   # 可調品質／尺寸
```

無縫做法：原圖鏡像拼成 2W×2H，取**中央 W×H**。鏡像對稱保證 `tile(0) === tile(W)`，
所以任意方向平貼都無接縫；代價是紋理內含一次鏡像重覆，因此來源圖要「低對比、無大疤」（本輪 oak 與
plaster 就是為了这点重生的）。腳本順手輸出 `tile-check-*.jpg`（2×2 平貼檢查圖）給人工看十字處。
plaster 另加 `-attenuate 0.10 +noise Gaussian` 打破對稱感——**不要對它用 `-level`**：米白牆平均亮度約 82%，
`-level 46%,54%` 會整張斷成純白（本輪踩過的坑，腳本註解已留警語）。

## 4. 載入、 basePath 與退回契約

- `src/lib/roomTextures.ts` 是唯一介接點：`attachPhotoMap(mat, key, opts)` 以 `THREE.TextureLoader`
  非同步換 `mat.map`，回傳 cancel／dispose 給呼叫端塞進 `disposers`；卸載或 React StrictMode
  雙掛載時不會把貼圖掛在已 dispose 的材質上。
- **部署前綴**：`assetUrl()` 用 `new URL(rel, document.baseURI)` 解析，所以 dev 是 `/textures/...`、
  GitHub Pages 專案頁是 `/test222/textures/...`，不需要把 `NEXT_BASE_PATH` 再多暴露一個 `NEXT_PUBLIC_*` 變數。
  `TEXTURES.dir` 因此**必須是相對路徑**（`check-room3d.ts` 會擋前導斜線）。
- **色彩空間**：照片貼圖一律 `SRGBColorSpace`（與既有 `canvasTexture()` 一致），anisotropy 取
  `min(8, renderer.capabilities.getMaxAnisotropy())`。
- **換圖時同時拉回底色**：程序化紋理的材質帶 `color`（會與 albedo 相乘），照片 albedo 已是成品色，
  因此換圖時用 `tint` 覆寫（書背例外：`#8b7a68` 主動壓暗）。
- **gate**：`scripts/check-room3d.ts` 新增貼圖資產檢查（六檔存在、>8 KB、`dir` 相對路徑、
  `floor` 只能是 `oak|marble`、`repeat` 為正數）→ 忘跑產圖腳本或誤刪資產會直接測掛，不會靜默變白模。

## 6. 已知限制

- 窗外照片只當**遠景平面**；前景樹冠、灌木、草地仍是程序化景片（留視差與投影用）。窗框影條仍來自實體幾何，
  捲簾刻意不投影，所以光帶與 v8.1 行為一致。
- 鏡像平貼在极低對比材質上仍殘留大尺度亮帶（plaster 約 ±1.6%），貼近牆面平視時可察覺；木紋、橡木、
  大理石不可見。要更乾淨就重生來源圖（提示詞加 `no large blotches`）再跑一次腳本。
- 本輪沒有瀏覽器自動化截圖與效能量測；簾面、燈帶亮度與手機側 frame time 需人工在預覽驗收
  （沿用 v8.1 §6 的驗收限制，發光片只增加 8 個 box，成本可忽略）。
- 參考圖樣張（主提示詞 A 與 6a／6b／6c）依使用者決定**留在沙箱 `/home/user/study-room-refs/`、不入庫**；
  主提示詞 B（以圖一為底、只換窗外）待圖一上傳後另行產出。
